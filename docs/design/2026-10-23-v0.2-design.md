# sendit v0.2.0 design: Settings, tray, persistent history

Builds on the v1 design (`2026-10-23-sendit-v1-design.md`). Goal: an app you can install and leave running, the version to post publicly.

## Decisions (agreed with the user)

- Settings is a **full page** that takes the place of the conversation pane. It opens from a **Settings** button next to our own name at the bottom of the sidebar.
- The **close (X) button** behaviour is a setting: *Keep running in tray* (the default) or *Quit*.
- **Start on sign-in** is **off by default**. The user turns it on.
- History keeps the **last 500** finished items and has a **Clear history** button. Clearing never deletes files.

## Settings

| Setting | Lives in | Takes effect |
|---|---|---|
| Device name (alias) | core, runtime-mutable | immediately. Changing it sends a new announcement. |
| Download folder | core, runtime-mutable | the next accepted request |
| PIN (off, or a value) | core, runtime-mutable | the next incoming request |
| Auto-accept per device | core trust store (exists) | immediately. The toggle only works for **verified** devices, because the core requires verification. Other devices show "verify it first to allow". |
| Close button: tray or quit | app | immediately |
| Start on sign-in | OS, via `tauri-plugin-autostart` | immediately. The value shown is read back from the plugin, not cached. |

**Core changes:** alias, pin and download_dir move from the immutable `Config` into a runtime `Settings` held behind a `Mutex` in `Inner`. `Config` still supplies the start values. New `Node::settings() -> Settings` and `Node::update_settings(Settings) -> Result<()>`:
- An empty or whitespace alias is rejected. Aliases are trimmed and capped at 64 characters.
- The download folder is created if missing. If it can't be created, the call fails and nothing changes.
- A changed alias triggers `send_announcement` when multicast is on.

**App persistence:** `settings.json` lives in the app data dir and holds `{ alias, downloadDir, pin, closeToTray }`. It is loaded at startup and fed into `Config`. It is saved after every successful `update_settings`. If the file is missing or corrupt, the app falls back to defaults: hostname, `Downloads/sendit`, no PIN, tray.

## Tray and window lifecycle

- A tray icon (the Buddy icon) shows the tooltip "sendit".
  - Left-click shows the window and focuses it, or hides it if it is already visible.
  - The menu has *Open sendit* and *Quit*.
- With closeToTray on, pressing X hides the window instead of closing it. The first time this happens, an OS notification says "sendit is still running in the tray".
- *Quit* (from the tray menu, or X with closeToTray off) shuts the node down and exits.
- Notifications fire for incoming requests and messages whenever the window is not focused, which already covers the hidden case.
- **Single instance:** launching sendit while it is already running brings up the existing window (`tauri-plugin-single-instance`). Without this, a second instance would fight over port 53317.

## Persistent history

- The app keeps `history.json` in the app data dir. It holds the finished tickets (statuses done, failed, declined, cancelled, expired, message), newest last, capped at 500. Transient fields are dropped (speed samples, `lastAt`).
- The frontend saves on change, debounced to 1 s, through a `save_history` command. It loads with `load_history` at start, before live events are applied.
- **Writes are atomic** (temp file, then rename) for `settings.json` and `history.json`, and the same fix applies to the core's `trust.json` (the deferred minor from the v1 review).
- A corrupt or unreadable `history.json` starts an empty history. The bad file is renamed to `history.json.bad`, so nothing is silently destroyed.
- Restored items whose files were moved or deleted show the type tile (existing fallback). *Show in folder* on a missing path shows an error banner.

## Error handling

- `update_settings` failures (bad folder, empty name) appear inline under the field, and the previous value is kept.
- Autostart plugin errors show the error banner, and the toggle snaps back to the real state.
- Save failures for settings or history show the error banner once. The app keeps working from memory.

## Testing

- **core:** `update_settings` validation, an alias change that is visible to peers through `/register`, a PIN change applied to the next request, and a download dir change applied to the next session. `TrustStore` save is atomic: the temp file is renamed and a crash leaves either the old or the new file.
- **app (Rust):** the settings and history file round-trip, the corrupt file fallback (with the `.bad` rename), the 500 cap, and the atomic write helper.
- **frontend (Vitest):** the Settings page renders values, edits call the bridge, and validation errors appear inline. The auto-accept toggle is disabled for unverified devices. History serialization drops transient fields and restores into the reducer.
- **e2e (Playwright, mock bridge):** open Settings, rename the device, toggle the PIN, clear history. A history item persisted by the mock shows up after a page reload.
- **Manual:** the tray menu, closing to tray, sign-in autostart, single instance. A real window and OS are needed for these.

## Out of scope

Thai locale, a settings sync between CLI and app (they keep separate data dirs), an auto-updater (next), a network interface picker.
